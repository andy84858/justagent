h4. As a
一般使用者，我希望在「我的技能」快速看到自己有哪些技能、用什麼方式建立的、大致啟用/觸發狀況，並能點一顆卡片進一步管理；AI 在對話中建議建立的技能，也要有地方集中處理。

h4. 功能說明
* *頁面結構*：「我的技能」與「團隊技能管理」是兩個獨立畫面（不是同一條 tab bar）。管理者會在 banner 右側看到「團隊技能管理」按鈕，進入後以「返回技能管理」回來，banner 標題隨之切換（見 SM-6）。
* *上方操作*：「瀏覽 Library」（開啟 Library 瀏覽視窗）、「建立技能」（三選一，見 SM-2）。
* *統計列*（只在「我的技能」畫面顯示）：
** 「{N}個技能等待審核」：實心 pill 按鈕（rust 色），僅企業/團隊管理者可見且件數 > 0 才出現，點擊切到團隊技能管理的「待審核」。
** 「{N}個 AI 建議技能待處理」：綠色 pill，有待處理建議就顯示（不分角色），點擊展開建議佇列並捲動過去。
** 啟用中技能／企業擴充／團隊擴充／本月自動觸發次數：色點＋數字＋文字樣式；數字取自 Library 技能（不是個人技能），觸發次數加千分位。
* *AI 建議建立的技能佇列*：
** AI 對話中判斷某流程值得建成技能時，會把建議放進佇列（以 id 去重），並在對話裡推一則單向通知：「我留意到「{reason}」這類流程你之後可能會重複用到，已經把建議放進「技能管理」…」。
** 佇列預設收合成一行摘要「{N} 個 AI 建議建立的技能」，點擊展開；展開後最大高度 120px，超過內部捲動。
** 每筆顯示建議名稱與「來自「{reason}」流程」，右側「不用了」（移除該筆）與「建立」（帶入預填草稿開啟 AI 賦能抽屜，並同時把該筆移出佇列）。
** 側欄「技能管理」連結也會顯示待處理建議數徽章（桌機／行動版皆有）。
** Demo 預設種 4 筆建議：週報摘要整理、客訴分類彙整、庫存異常示警、會議行動項目追蹤。
* *個人技能卡片*（PersonalSkillGroup）：
** 依建立方式顯示圖示：有 composition → 積木圖示；creationMethod=ai_assisted → 對話圖示；沒有 forkSourceId／derivedFrom → 鉛筆圖示；其餘（例如複製副本）→ 人形圖示。
** 描述優先顯示第一筆使用情境標題，沒有才顯示技能描述。
** 只有「草稿」「審核中」顯示狀態標籤。
** 狀態文字依序判斷：啟用中 → 尚未測試（aiTestPassRate 為 null）→ 停用中；觸發次數顯示「{n} 次觸發」（≥1000 顯示如「1.2k」）。
** 卡片本身沒有操作按鈕，點整張卡片開啟技能詳情抽屜。
* *技能詳情抽屜*：狀態文字為「啟用中／尚未測試／已停用」；啟用中且曾「視為通過」強制啟用的技能，旁邊加 warning 圖示（title「測試沒有全對，使用者選擇直接啟用」）。審核中的個人技能不顯示「編輯」「送審」，也不能切換啟用。
* *編輯入口*：積木組裝技能按「編輯」直接開積木抽屜；其他技能跳出「跟 Agent 對話修改」／「直接編輯」二選一。
* *空狀態*：「透過對話生成技能，或手動建立 skill 檔案後，技能會出現在這裡」。
* *分頁*：每頁 10 筆，總頁數 > 1 才顯示分頁器（左右箭頭＋「{current} / {total}」）。

h4. Acceptance Criteria

- [ ] 待審核 pill 僅管理者可見且件數 > 0 才顯示，點擊進入團隊技能管理「待審核」
- [ ] 有待處理 AI 建議時顯示建議 pill，點擊展開佇列並捲動過去
- [ ] 其餘四項為色點+數字+文字樣式，數字來源為 Library 技能
- [ ] 統計列只在「我的技能」畫面顯示

*AC2：AI 建議佇列*
- [ ] 預設收合成一行摘要，點擊才展開；超過高度時內部捲動
- [ ] 「建立」開啟 AI 賦能抽屜並帶入預填草稿，該筆同時移出佇列
- [ ] 「不用了」直接移除該筆
- [ ] 側欄「技能管理」顯示待處理建議數

*AC3：技能卡片與詳情*
- [ ] 圖示判斷順序：composition → ai_assisted → 無來源血緣（鉛筆）→ 其餘（人形）
- [ ] 有使用情境時顯示第一筆標題，否則顯示技能描述
- [ ] 只有草稿/審核中顯示標籤
- [ ] 狀態文字依序：啟用中 → 尚未測試 → 停用中
- [ ] 點卡片開啟詳情抽屜；強制啟用的技能顯示 warning 標記
- [ ] 積木技能「編輯」直接開積木抽屜，其他技能跳出修改方式二選一

*AC4：分頁*
- [ ] 每頁 10 筆，超過一頁才顯示分頁器

h4. Out of Scope

* 卡片寫「停用中」、詳情抽屜寫「已停用」，用詞不一致。

h2. [AI副作平台 / Skill管控後台] SM-2 ｜ 建立技能入口三選一與手動建立精靈

|| 欄位 || 內容 ||
| 所屬單元 | 技能管理 |
| 前置 Story | SM-1 |
| 狀態 | 已完成開發 |

----

h4. As a
想建立新技能的使用者，我希望一開始就能選擇最適合我的建立方式；手動建立時能照著清楚的步驟填完必要內容，並在建立後馬上測試。

h4. 功能說明
* *三選一*：「建立技能」跳出選擇框（說明「要用哪種方式建立這顆技能？」），選項：「用對話建立」、「用行銷積木組裝」→ 直接開啟 AI 賦能抽屜並指定方式（見 SM-3／SM-4）；「手動建立」→ /view/SkillEditor。
* *SkillEditor 精靈步驟依模式不同*：
** 全新建立：4 步「基本資訊 → 技能指令 → 確認 → 測試」。
** 編輯既有技能（?skillId=）、繼續編輯草稿（?draftId=）：3 步「基本資訊 → 技能指令 → 確認」。
* *Step 基本資訊*：只有「技能名稱 *」（上限 40 字），名稱填了才能下一步。（原「技能描述」唯讀區塊已移除。）
* *Step 技能指令*：技能指令（顯示字元數）、「觸發時機 *」（上限 300 字）、「覆蓋能力 *」、「指派 Agent *」（共用 AgentAssignGrid，至少一位）。所需檔案上傳已從精靈移除。
* *覆蓋能力*：hashtag 標籤，Enter 或失焦新增；空白分隔可一次輸入多個；不重複加入；提供 7 個常見標籤 chip（問題分類、資料查詢、內容摘要、格式轉換、多語言支援、情緒風險辨識、資料整合），已加入的 disable 並打勾；可移除。
* *必填檢查時機*：技能名稱卡在第一步；觸發時機／覆蓋能力／指派 Agent 只在最終送出那一刻檢查（全新建立是確認步驟的「下一步」，編輯/草稿是送出按鈕），缺欄位時 footer 顯示「請先填寫：…」。例外：編輯模式從停用切成啟用時不檢查指派 Agent（交給 SM-5 的 Agent 確認步驟）。
* *Step 確認*：「內容摘要」（指令字元數、觸發時機、覆蓋能力項數）與「設定」（指派 Agent）。編輯模式另有啟用狀態切換，切成啟用送出時走 SM-5 啟用流程。
** 全新建立：主按鈕是「下一步」，提示「下一步會先建立這顆技能（預設未啟用），再進「AI 快速測試」驗證。」——按下即建立技能（重複來回不會建第二顆）。
** 編輯模式：主按鈕「儲存變更」，提示「儲存後變更立即生效。」
* *Step 測試（僅全新建立）*：
** 提示「技能已建立（未啟用）。AI 會自動產生測試情境，通過後就能啟用；也可以先略過，之後再回來測試。」，內嵌 AI 快速測試（見 ST-2）。
** 完成按鈕：還沒生成測試情境時為「不啟用，建立完成」（可直接按）；生成後改為「測試完成，建立完成」，需全部題目作答並送出才能按。兩者都回到 /view/Skills。
** 測試全對且技能未啟用時，測試報告會出現「啟用技能」按鈕（走 SM-5）。
** 從測試步驟按「上一步」會清空這輪測試情境，再進測試步驟需重新生成。
* *步驟鎖定*：技能建立後，「基本資訊」「技能指令」鎖住不能回去；「確認」「測試」之間可來回。
* *取消／放棄修改*：編輯模式顯示「放棄修改」，建立/草稿模式顯示「取消」，都回 /view/Skills 不寫回資料；測試步驟不顯示。已建立的未啟用技能會保留。
* 新建技能一律落地到「我的技能」，狀態未啟用、未測試，不需送審即可個人使用。

h4. Acceptance Criteria

*AC1：選擇框*
- [ ] 三個選項：用對話建立／用行銷積木組裝／手動建立
- [ ] 對話／積木直接開啟 AI 賦能抽屜並指定方式
- [ ] 手動建立導向 /view/SkillEditor

*AC2：精靈步驟與必填*
- [ ] 全新建立 4 步、編輯/草稿 3 步
- [ ] 技能名稱必填才能離開第一步
- [ ] 觸發時機／覆蓋能力／指派 Agent 為必填，只在最終送出時檢查，缺欄位時顯示「請先填寫：…」
- [ ] 精靈中不再有技能描述與檔案上傳欄位

*AC3：建立與測試*
- [ ] 全新建立在確認步驟按「下一步」即建立技能（未啟用），來回切換不重複建立
- [ ] 建立後無法回到前兩步
- [ ] 未生成測試時完成按鈕為「不啟用，建立完成」；生成後為「測試完成，建立完成」且需全部作答送出才能按
- [ ] 從測試步驟按「上一步」會清空測試情境

*AC4：覆蓋能力*
- [ ] Enter 或失焦新增，可一次輸入多個（空白分隔），不重複加入
- [ ] 提供 7 個常見標籤，已加入的 disable 並打勾；可移除

h4. Out of Scope
* 對話建立／積木組裝流程，見 SM-3／SM-4
* AI 快速測試判題邏輯，見 ST-2

h4. 待確認
* 草稿模式最後一步按鈕寫「建立技能」，實際只更新草稿、不建立技能。
* 既有技能的 files 仍會帶進 payload，但精靈已沒有欄位可編輯。

h2. [AI副作平台 / Skill管控後台] SM-3 ｜ AI 賦能技能建立與編輯（抽屜整合）

|| 欄位 || 內容 ||
| 所屬單元 | 技能管理 |
| 前置 Story | SM-2 |
| 狀態 | 已完成開發 |

----

h4. As a
想快速建立/調整技能的使用者，我希望透過跟 AI 對話描述需求，由 AI 擬出技能設定；存檔前就能先測試，測完可以直接儲存並啟用，整個流程都在技能管理頁的抽屜裡完成。

h4. 功能說明
* *抽屜與路由*：AI 賦能掛在 /view/Skills 的抽屜（SkillStudioDrawer），開關由 query skillId／method／from 決定，tab／intent 控制內容；舊 /view/SkillStudio 會 redirect 並保留 query。
* *開場白依進入方式不同*：
** 建立技能選對話：「你好，我是技能建立助理。跟我說說你想讓 Agent 幫你做什麼，我會先幫你擬一版設定內容。」
** 從技能編輯：「你好，我們來調整「X」。告訴我想改哪裡，右側會即時反映。」
** 從測試沙盒「詢問技能助理」（intent=ask）：「你好，我是這裡的助理。剛剛測試「X」時如果有哪裡想確認或討論，都可以直接問我…」
** 從 AI 建議佇列（from=）：使用交接時帶入的開場白（見 SM-1）。
* *對話建立*：AI（mock 規則式）逐步收集技能名稱／指令／觸發時機／覆蓋能力，右側即時預覽。
* *存檔前先測試*：還沒存檔時測試 tab 就能出題作答（用暫時 id），存檔後測試結果轉移到正式技能；草稿內容在出題後有變動時顯示「內容已變更，建議重新生成測試情境」。
* *出題過程寫進對話*（僅對話方式）：生成中的敘事（查看可調用 Agent、找到相似技能）會成為 Agent 訊息，完成後推「題目生成完成，可以開始作答囉！」。技能還沒指派 Agent 時，會依內容推測團隊內相似的技能並借用它的 Agent 出題。
* *測試結果回饋*：
** 沒全對：對話推「剛剛的測試沒有全部通過（答對 X/Y，Z%），要不要跟我說說看哪裡需要調整？…」，不附快捷按鈕，接續收集修正內容；使用者打「重新測試」類句子會換一批題目，打「直接啟用」類句子會覆蓋啟用（已存檔時）。
** 全對：依狀態推三種訊息之一（未存檔 → 提醒先儲存；已存檔已啟用 → 不用再做事；已存檔未啟用 → 到測試報告點「啟用技能」）。
* *固定底欄*（不隨右側 tab 切換消失）：
** 儲存按鈕：有測試紀錄時為「儲存並啟用」（先存檔再走 SM-5 啟用流程，已啟用的不會被切回停用）；否則建立模式「儲存為個人技能」、編輯模式「儲存修改」。
** 存檔成功：建立模式 toast「已儲存為個人技能，可到「測試」tab 驗證」並自動切到測試 tab；編輯模式 toast「已儲存修改」。
** 「放棄修改」：僅編輯模式（含建立後已存檔）出現，有變更時先確認「有未儲存的變更，確定要放棄嗎？」，確認後還原成已儲存版本並關閉抽屜。
* *未儲存變更保護*：query 改變時確認「有未儲存的變更，確定要放棄嗎？」；離開 /view/Skills 時確認「有未儲存的變更，確定離開？」。
* *編輯中想開新技能*：編輯模式下說出想建新技能的句子，Agent 會問「你是想先放下目前的修改，開始建立一份全新的技能嗎？」，附「對，開新的」／「不是，我想問別的」；確認後丟棄修改並切到新建對話。
* *Library 技能*：不能直接在抽屜編輯，會提示「Library 技能請先在技能管理複製為個人技能」。

h4. Acceptance Criteria

*AC1：抽屜與路由整合*
- [ ] 抽屜開關由 /view/Skills 的 query 決定，沒有獨立路由
- [ ] 舊 /view/SkillStudio 連結導回 /view/Skills 並保留 query
- [ ] 建立／編輯／詢問／建議交接四種進入方式顯示不同開場白

*AC2：對話建立與編輯*
- [ ] 可用文字逐步收集技能名稱／指令／觸發時機／覆蓋能力，即時反映在預覽
- [ ] 編輯中要求開新技能時先在對話中確認，確認後丟棄修改並切到新建

*AC3：存檔前測試與出題敘事*
- [ ] 未存檔即可測試，存檔後測試結果保留在正式技能上
- [ ] 出題後內容有改動時提示重新生成
- [ ] 對話方式的出題敘事與完成提示會出現在對話中

*AC4：測試結果回饋*
- [ ] 沒全對時推含正確率的引導訊息（無快捷按鈕），可接續收集修正
- [ ] 全對時依「未存檔／已啟用／未啟用」推對應訊息

*AC5：儲存與放棄*
- [ ] 有測試紀錄時按鈕為「儲存並啟用」並走 SM-5 啟用流程；否則依模式為「儲存為個人技能」／「儲存修改」
- [ ] 建立模式存檔後自動切到測試 tab
- [ ] 「放棄修改」還原成已儲存版本並關閉抽屜，有變更時先確認
- [ ] 有未儲存變更時，切換 query／離開頁面都會先確認

h4. Out of Scope
* 積木組裝面板，見 SM-4
* AI 快速測試判題邏輯，見 ST-2
* 手動建立精靈，見 SM-2

h4. 待確認
* 未存檔時使用者打「直接啟用」，Agent 也回覆「已啟用」，但實際上沒有啟用任何東西。
* 全對且未存檔時的訊息寫「先按左下角「儲存」」，但當下按鈕實際是「儲存並啟用」。

h4. 功能說明

** 三個選項：「立即測試」、「視為通過，直接啟用」（標記覆蓋後進第二關）、「取消」。點遮罩等同取消。

* *第二關（確認 Agent）*：標題「啟用「{name}」」，說明「確認哪些 Agent 可以調用這個技能，之後隨時可以再調整。」，預設勾選技能目前的 assignedAgents，至少選一個才能按「確認並啟用」。
* *停用*不經過任何對話框。
* *強制啟用標記*：用「視為通過」啟用的技能，在卡片/詳情狀態旁顯示 warning 圖示（「測試沒有全對，使用者選擇直接啟用」）；之後測試全對或重新生成題目時清除標記。
* *呼叫端（4 個）*：
*# 技能詳情抽屜的「啟用技能」按鈕（SkillManagement）——列表卡片上沒有開關。
*# 手動編輯精靈編輯模式，把啟用狀態切成開並送出（Agent 清單透過 updateSkill 寫回）。
*# AI 快速測試報告的「啟用技能」（已存檔、未啟用、100% 全對）與「儲存並啟用」（未存檔但有測試報告）。
*# AI 賦能抽屜底欄的「儲存並啟用」（見 SM-3）。

h4. Acceptance Criteria

*AC1：測試閘門*
- [ ] 個人技能未測試或未全對時，啟用會先跳出閘門對話框
- [ ] 文案依「未測試過」／「未全對」顯示不同原因
- [ ] 已通過、已覆蓋或 Library 技能直接進入 Agent 確認
- [ ] 「立即測試」在同一對話框內測試，全部答對後才能「繼續啟用」

*AC2：確認可調用的 Agent*
- [ ] 預設帶入技能目前的 assignedAgents
- [ ] 至少選一個 Agent 才能「確認並啟用」
- [ ] 確認後才寫回 Agent 清單並啟用（覆蓋旗標一併寫回）

*AC3：取消、停用與標記*
- [ ] 任一步驟取消都不改變啟用狀態與 Agent 指派
- [ ] 停用不跳任何對話框
- [ ] 強制啟用的技能顯示 warning 標記，測試全對或重新出題後清除

*AC4：呼叫端一致*
- [ ] 詳情抽屜、手動編輯精靈、AI 快速測試報告、AI 賦能抽屜底欄四處都走同一套流程

h4. Out of Scope
* AI 快速測試判題與計分，見 ST-2

h4. 待確認
