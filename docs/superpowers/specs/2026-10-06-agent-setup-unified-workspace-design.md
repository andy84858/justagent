# Agent 基礎設定：單一工作區重設計

本文件推翻原本《UI_Agent 基礎設定 Demo 設計》裡「①素材庫 ②NPC ③人物卡 ④組合包／擴充包」四個獨立分頁的流程，改成一個常駐式單一工作區。⑤企業訂閱頁不在本次重設計範圍內，維持獨立頁面。

> [!info] 與原文件的關係
> 原文件：[[UI_Agent 基礎設定 Demo 設計]]（使用者在對話中貼出全文，原始 vault 路徑 `JustAgent/UI草稿/Agent基礎設定demo/`，本機無法存取實體專案檔案）。
> 本次只推翻「五頁分法的流程」，其餘既有設計決策（視覺規格、互動規則、檢核邏輯）原則上沿用，詳見〈沿用不變的部分〉。

---

## 背景與問題

原設計把「建立一個可用的 agent 變體」拆成跨頁流程：素材庫（建寶石／裝備）→ NPC（建主檔／模型）→ 人物卡（組裝能力、發布）→ 組合包／擴充包（打包發佈）。

實際使用時最大的痛點是**頁太多、步驟太繁瑣**：編輯人物卡的能力區時，若發現缺一顆寶石，必須先跳回素材庫頁新建，再跳回人物卡頁才能裝備。四個頁面各自獨立導覽，使用者得自己在頭腦裡串起「這些頁面其實是同一件事」。

## 目標

把①②③④整合成一個不需要切換頁面就能完成「建 NPC → 建人物卡 → 組裝能力 → 打包發佈」全流程的單一工作區。⑤企業訂閱的使用者是企業方、不是建 agent 的人，維持獨立頁面不動。

---

## 整體架構：三欄常駐式工作區

```
┌──────────┬────────────────────────────┬──────────────┐
│          │                            │              │
│ 左欄      │         中欄                │    右欄       │
│ 導覽樹    │       編輯焦點              │    背包       │
│ 220px    │        彈性寬                │    300px     │
│          │                            │              │
└──────────┴────────────────────────────┴──────────────┘
```

- 左欄：NPC／人物卡導覽樹，決定中欄顯示什麼。
- 中欄：依左欄選取，顯示 NPC 主檔＋模型設定，或人物卡編輯（分頁＋能力區）。
- 右欄：背包，常駐顯示，取代獨立素材庫頁；平常窄、需要完整細節時滑出寬面板蓋住中欄左側。
- 組合包／擴充包：不另開頁面，借用右欄的空間切換成「打包」模式。

比例取自 1440 寬：左 220px（固定）／右 300px（固定，滑出時擴為 460px 疊加）／中欄彈性吃掉剩餘寬度。

---

## 左欄：導覽樹

- 樹狀結構：NPC（可展開／收合）→ 底下列出其所有人物卡。
- 點 NPC 本身 → 中欄切到「NPC 焦點」。
- 點人物卡 → 中欄切到「人物卡焦點」。
- 樹狀節點顯示：NPC 用頭像 emoji＋`agent_code`；人物卡用名稱＋已發布版號（`已發布 vN`）或「尚未發布」的輕量標示（例如灰字版號對比有色版號，沿用原本「已發布 vN／尚未發布」文案，不用徽章搶視覺）。
- 「＋ 新增 NPC」固定在樹狀最下方，沿用原本代碼規則與檢核（[[C1_Agent 變體#建立]]、`agent_code` 檢查 `^[A-Z0-9_]{1,80}$`，代碼＋場域不可重複）。
- 每個 NPC 節點展開後，最下面一列是「＋ 新人物卡」：
  - 點下去變成 inline 小表單（代碼、名稱兩個輸入框＋「建立」「取消」），**不用原本的翻牌動畫**——翻牌的視覺前提是「人物卡橫排成同一排卡片」，這個前提在新版面裡不存在了（人物卡現在是樹狀節點，不是橫排卡片）。
  - 代碼規則沿用 [[C1_Agent 變體#建立]]：`^[A-Z0-9_]{1,40}$`，同 agent 內不可重複，建立後不可改。
  - 建立成功 → 該人物卡節點出現在樹上並自動選中，中欄開始編輯；取消或點別處 → 表單收起。
- `SWITCH` 型 NPC（原文件的 `INTENT_SWITCH`）在樹上顯示為淡色，點「＋新人物卡」擋下，理由同原文件：只有 `AGENT` 型能建立變體。

### 待決項目

- 人物卡很多時，樹狀要不要搜尋／篩選，本次先不處理，列入〈已知限制〉。

## 中欄：編輯焦點

### 選中 NPC 本身

顯示 NPC 主檔＋模型設定，內容與互動**直接沿用原文件②頁**，只是從獨立頁面搬進中欄：

- 主檔：`agent_code`、`agent_type`、`agent_used_for` 建立後 🔒 不可改；右上角鉛筆編輯名稱、頭像等可改欄位。
- 加入模型：依供應商樣板帶入參數，樣板或參數對應表不存在時擋下。
- 模型參數：只能改 `value`，存檔時檢查型別與數值範圍，列舉值警告不擋。
- 發布模型：有未儲存修改時擋下；必填參數不可空；版號＝最大值 +1。

### 選中人物卡

沿用原文件③頁「編輯人物卡」的卡片區塊設計，整塊搬進中欄，**版面與互動規則不變**：

- 標題列：公開記錄按鈕、發布狀態（已發布 vN／尚未發布）、儲存狀態（已儲存／有未儲存的修改）、放棄修改／儲存／發布按鈕。發布與公開記錄維持彈窗形式（原本就是浮在頁面上，不受版面搬動影響）。
- 左欄頭像 160px；右側三分頁（基本資料、模型、基礎指令）各自獨立鉛筆編輯，固定高度（唯讀值與輸入框等高，說明欄固定 76px、基礎指令固定 200px）。
- 能力區（🎒）直接沿用原文件的子區劃分：裝備欄、佩掛寶石，固定高度、框內捲動。**背包子區不再放在能力區裡面——改成固定在右欄**，見下一節。能力區的裝備欄／佩掛寶石的卸下（⊖）、詳情（⋯ 滑出）等互動維持不變。

## 右欄：背包（取代獨立素材庫頁）

這是本次整合裡變動最大的一塊，分兩個狀態：

### 狀態一：窄背包（平常，300px）

- 內容對應原文件③頁能力區的「背包」子區：分類鈕（全部／裝備／寶石）、搜尋放大鏡、漏斗篩選（顯示全部／顯示已裝備的）、▦／☰ 切換格子或清單。
- 格子／清單點擊＝直接穿上或佩掛（已裝備再點一次＝卸下），規則沿用〈寶石置換規則〉表格，一步完成、不需要先滑出詳情。
- 草稿格維持灰階、不可選、`aria-disabled`，點擊由程式擋下並說明原因。
- 標題列多一個「＋ 新增」，取代原素材庫頁的「＋ 新增寶石／＋ 新增裝備」入口。

### 狀態二：滑出詳細面板（460px，蓋住中欄左側）

觸發時機：點背包物品的「⋯」、點「＋ 新增」、或在詳情裡要編輯／管理版本。

- 滑出面板從右欄左緣再往左滑出，中欄同時變暗、`inert`（暫停互動），面板本身可捲動。
- 面板內容＝**原文件①素材庫頁「右區：完整詳細」的完整功能**，原樣搬過來：
  - 標頭：大圖示、類型標籤、顯示名稱、名稱、鉛筆。
  - 等級按鈕列（`[Lv1][Lv2][Lv3][Lv4 草稿]`），切換只換面板內容。
  - 寶石：基本資料、種類／協定意義、從哪一級複製、被引用清單（裝備、人物卡）。
  - 裝備：基本資料、鑲嵌寶石、從哪一級複製、被哪些人物卡掛載。
  - 動作列固定在面板底部：依狀態顯示「開 LvN 草稿」或「公開、刪除」。
  - 鉛筆就地編輯、✓ 儲存，規則沿用原文件〈編輯〉表格（名稱不可改、公開版只能改顯示名稱、寶石只有新建立的草稿能換種類／協定、裝備草稿被掛載時鑲嵌鎖住）。
  - 「＋ 新增」也在這個面板裡完成：標頭寫新增寶石或新增裝備，底部固定「建立 Lv1 草稿」「取消」。
- ✕ 或 Esc 收回面板，回到狀態一；焦點依原規則移動（開啟時焦點到 ✕／第一個欄位，關閉時 `inert`）。
- 書籤（全部／API／MCP）這次**拿掉獨立的框外書籤直排**，併入窄背包的篩選（跟分類鈕合併，或維持漏斗選單擴充一個「種類」篩選）——因為框外書籤原本是為了素材庫左右兩欄的寬版面設計的，300px 窄欄放不下；具體 UI 留到下一輪人物卡頁等級的細部設計再定，本文件先記錄「書籤併入既有篩選機制」這個方向。

---

## 組合包／擴充包：右欄的「打包」模式

- 人物卡中欄標題列新增「打包」按鈕（置於發布按鈕群組旁）。
- 點下去，右欄從「背包」切換成「打包」模式（兩者互斥，同一時間右欄只能是其中一種）：
  - 組合包：勾選一張或多張**已發布**的人物卡（含目前這張），同場域限制沿用；確認後送出。
  - 擴充包：先選適用 agent，再勾選公開的裝備或寶石，同名只放一個等級。
- 打包模式一樣有窄／滑出兩態：窄態列清單＋勾選，滑出態看單一組合包／擴充包的完整內容與生命週期操作。
- 生命週期規則**完全沿用**原文件：`DRAFT → PUBLISHED ⇄ MAINTENANCE → EOS`；`DRAFT` 可直接 `EOS`；離開 `DRAFT` 後只能改顯示名稱與說明。
- 右欄標題列一個切換鈕在「背包」與「打包」之間切換，離開人物卡焦點（例如切到別的人物卡或 NPC）時自動切回「背包」。

## 已知限制與待辦

| 項目 | 說明 |
| --- | --- |
| 響應式版面 | 原文件的 960px／860px 斷點是為五頁各自版面設計的，三欄常駐版面（左220＋右300固定）在窄螢幕下如何收合（例如左欄收成純圖示、右欄收成浮動按鈕喚出）本文件未定義，需要下一輪設計 |
| 書籤篩選併入窄背包 | 「併入既有篩選機制」的具體 UI（分類鈕旁加種類篩選？漏斗選單擴充？）留待下一輪 |
| Esc 關閉順序 | 新增了「背包滑出面板」「打包模式」兩種可關閉層，原本的 Esc 關閉順序（發布彈窗→公開記錄彈窗→背包篩選選單→背包詳情卡）需要重新排序，留待下一輪 |
| 樹狀導覽的搜尋／篩選 | NPC／人物卡數量多時的瀏覽方式，本次未設計 |
| 組合包/擴充包的同名衝突、企業端合併規則 | 沿用原文件既有的「待定」狀態，不在本次範圍內解決 |
| 測試涵蓋 | 原文件有 226 項 UI 測試（`tests/ui.test.cjs`），版面重構後需要大量改寫，不在本次設計範圍，留待實作階段規劃 |
