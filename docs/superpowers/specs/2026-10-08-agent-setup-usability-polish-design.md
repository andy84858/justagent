# Agent 配置工作區：易用性優化設計

本文件是 [[2026-10-06-agent-setup-unified-workspace-design]]（三欄常駐式工作區）完成後的一輪易用性優化，不改變既有的資料模型、檔案結構或 Phase 1-4 已經實作的功能邏輯，只調整畫面呈現與互動方式。

## 背景與問題

Phase 1-4 把「素材庫／NPC／人物卡／打包」整合成一個三欄常駐式工作區後，使用者實際操作時回報三類問題：

1. **操作流程不直覺**：左側導覽列點了沒反應（要精準點小箭頭才會展開）；建立擴充包時一長串表單看不出先後順序；打包模式的「＋新增組合包」「＋新增擴充包」兩顆按鈕同時出現，不管在看哪個分頁都會看到，容易點錯。
2. **資訊層級不清楚**：發布檢核擋下時所有理由擠成一句用「；」分隔的長句子；公開記錄看不出哪一版是現在用的；生命週期狀態顯示英文代號（`DRAFT`／`PUBLISHED`...）。
3. **按鈕等等不明顯，不知道怎麼用**：disabled 的按鈕跟一般按鈕視覺上差不多，不知道為什麼按不下去；同一個工具的不同版本在打包勾選清單裡用獨立 checkbox 呈現，看不出「只能選一個」；技能帶入的工具跟自己另外佩掛的工具混在同一個清單裡，看不出誰帶誰；工具庫裡會跟目前狀態衝突的項目要點下去才跳警告，不能一眼看出哪些不能選。

本文件逐項定義修正方式，全部延續 [[2026-10-06-agent-setup-unified-workspace-design]] 已經確立的三欄架構與 Phase 1-4 的底層規則（寶石置換規則、生命週期表、場域限制等），只動畫面。

## 視覺方向

整體走「精簡留白＋清楚主次」：

- 拿掉不必要的區塊外框，用字重、顏色、間距分主次，而不是每個區塊都包一層框線。
- **disabled 的動作一律改成灰字＋原生 `title` 提示**（滑鼠移上去說明為什麼不能按），不再用看起來像按鈕、但點不下去的灰色按鈕——同一個畫面裡最多只有一顆實心主色的主要按鈕，其餘是外框或純文字次要動作。
- 狀態一律用「小圓點＋文字」表示（例如紫色圓點＝已啟用、灰色圓點＝可用、淺灰圓點＝草稿鎖定），不用大面積色塊徽章；只有組合包/擴充包的生命週期狀態維持徽章（因為狀態本身就是這個畫面的主要資訊），但徽章文字改成中文。

## 左側導覽：NPC → Agent，點整列展開

- 「NPC」全面改名為「**Agent**」（對照 [[2026-10-06-agent-setup-unified-workspace-design]] 沿用的原文件定義：NPC＝agent 主檔＋模型），包含導覽列標題「Agent／人物卡」、「＋新增 Agent」按鈕、代碼重複的錯誤訊息、模型鎖定提示文字、空狀態提示文字。
- **點擊整列（圖示＋名稱＋箭頭）只負責展開／收合**底下的人物卡清單，不會同時跳去選取或編輯 Agent 主檔——原本「點名字＝選取、點箭頭＝展開」兩種點法合併成一種，整列都是有效點擊區，hover 時整列反灰，箭頭會依開合狀態旋轉。
- 展開後，變體清單上方多一條獨立的「**⚙️ Agent 設定**」入口（跟變體清單之間用一條虛線隔開），專門用來進入 Agent 主檔編輯畫面（代碼／類型／場域／模型設定）；這是目前底下 Phase 1 就有的那個主檔編輯畫面，只是改變入口方式，畫面內容不變。
- 「＋新增人物卡」維持在變體清單最下面，位置與行為不變。

## 打包模式

### 新增按鈕跟著分頁走

- 目前「＋新增組合包」與「＋新增擴充包」兩顆按鈕同時顯示，不論使用者在「組合包」或「擴充包」哪個分頁。改為**只顯示跟目前作用中分頁對應的那一顆**：在「組合包」分頁只看到「＋新增組合包」，切到「擴充包」分頁才看到「＋新增擴充包」。

### 建立流程改成「步驟」感

- 擴充包建立表單目前是一長串（選 Agent、勾選項目、填代碼與顯示名稱）平鋪在同一畫面。改為三個帶編號的區塊：①選擇適用 Agent → ②勾選要放入的工具／技能 → ③命名，視覺上用淡框＋編號圓圈區隔每個步驟，但維持同一頁、不拆成真正的多步驟精靈（不需要「上一步/下一步」，因為表單本身不長，只是需要清楚的分段視覺）。
- 組合包建立表單（勾選同場域已發布的人物卡＋命名）比照同樣的分段邏輯，只是少一個「選 Agent」的步驟。

### 生命週期狀態改成中文徽章

| 系統狀態（不變） | 畫面文字 | 顏色 |
| --- | --- | --- |
| `DRAFT` | 草稿 | 灰 |
| `PUBLISHED` | 已上架 | 綠 |
| `MAINTENANCE` | 維護中 | 橘 |
| `EOS` | 已下架 | 紅 |

只改顯示文字與顏色，`wsPackNextStatuses` 定義的合法轉移規則、按鈕的顯示/隱藏邏輯完全不變。

## 發布與公開記錄

### 發布檢核：清單取代長句子

- 目前 `wsPublishVariantErrors`／`wsPublishModelErrors` 回傳的錯誤陣列在彈窗裡用 `errors.join('；')` 接成一句話顯示。改為**逐條列出**，每條前面打勾（通過的規則，綠色 ✓，灰字說明文字）或打叉（擋下的規則，紅色 ✕，寫清楚原因與下一步該做什麼，例如「有未儲存的修改，請先點標題列的「儲存」」）。
- 檢核邏輯本身（哪些規則、什麼時候擋）完全不變，只是把「陣列」直接渲染成清單，而不是 join 成一句話再顯示。

### 公開記錄：標出目前版本

- 公開記錄彈窗目前只列出「版號＋時間」。改為把**目前生效的版本特別標示**（淡色底＋「目前」小徽章），其餘版本維持原樣的列表呈現。資料來源（`publishHistory`、`publishedVersion`）不變，只是渲染時多判斷一次「這一列是不是 `publishedVersion`」。

## 擇一規則與技能帶工具的視覺化

這段對應「按鈕選項不明顯」裡最具體的三個場景，三個一起做：

### A. 打包勾選清單：同名分組＋單選鈕

- 擴充包建立表單與既有擴充包的成員編輯器（`wsCommitPackMembers` 對應的那個勾選清單）裡，目前每個「工具/技能＋版本」都是一個獨立的 checkbox，使用者看不出「同一個工具只能選一個版本」。
- 改為**依名稱分組**：同一個工具名稱底下的所有已公開版本放在同一個群組框裡，群組內用**單選鈕（radio）**呈現（含一個「不加入」選項），群組下方加一行小字「同一個工具只能選一個版本」。
- 底層資料結構（`selectedItems`/`packMembershipDraft` 陣列、`wsToggleExtensionItemSelection`/`wsToggleMembershipDraftItem` 的「選新的就頂掉舊的」邏輯）不變，只是把渲染從「每個版本一個 checkbox」改成「每個名稱一組 radio」。

### B. 能力區：技能帶的工具 vs 自己佩掛的工具

- 人物卡編輯畫面的「能力」區（`renderAbilityArea`）目前把「技能帶入的工具（鑲嵌）」跟「使用者自己另外佩掛的工具」分別顯示在「技能欄」跟「佩掛工具」兩個子區，但使用者反應看不出兩者的關聯——哪些工具是因為穿了某個技能才出現的，不夠直覺。
- 維持現有兩個子區的架構（技能欄／佩掛工具欄），但**技能欄裡每個技能底下，把它鑲嵌帶入的工具用縮排＋淡紫色「鑲嵌」小標籤列出**，讓「這個工具是因為穿了這個技能才有的」一目了然；「佩掛工具」子區維持原樣，只列使用者自己另外佩掛、技能沒有帶入的工具。
- 這只是調整 `renderAbilityArea` 的渲染方式（把 `wsCarriedGems` 已經算好的鑲嵌清單接到對應技能底下），不改變卸下、置換等任何互動邏輯。

### C. 工具庫：會衝突的版本先變灰

- 目前工具庫列表點擊才會跑 `wsWearGem`/`wsEquipEquipment` 的置換規則試算，衝突時才跳錯誤訊息。使用者希望**還沒點之前就看得出哪些版本點了會衝突**。
- 渲染工具庫列表時，對每一列**先用現有的置換規則函式試算一次**（不實際寫入狀態，只讀結果）：如果這個版本會與目前已啟用的技能/工具衝突（同名不同版本已被佔用），該列直接**變灰、不可點擊**，並用 `title` 提示寫清楚衝突對象（例如「已透過『訂單查詢術』啟用 Lv2，無法同時佩掛不同版本」）。
- 這是三項裡實作成本最高的一項：工具庫列表目前是單純讀資料渲染，加這個之後**每一列都要多跑一次置換規則的純函式試算**（複用既有的 `wsWearGem`/`wsEquipEquipment` 邏輯，但不真的呼叫會寫入狀態的版本，而是抽出一個唯讀的「試算」版本）。使用者已確認接受這個成本，三項一起做。

## 範圍外

- 不改動任何資料模型、`SEED` 結構、`uiState` 欄位新增以外的狀態邏輯、生命週期轉移規則、寶石置換規則本身的判定邏輯。
- 不處理響應式／窄螢幕版面（沿用 [[2026-10-06-agent-setup-unified-workspace-design]] 已知限制清單裡列的待辦）。
- 不處理 Phase 4 之後規劃但尚未排入時程的功能（企業訂閱頁等）。
